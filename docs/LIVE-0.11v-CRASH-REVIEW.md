# 0.11v live-client crash and VR input review

Working-tree hotfix against release `1045602`. Test candidates are separate from the published release. The observed live server was inspected without changing its configuration, matches or process.

## Findings and changes

- Three Linux client SIGSEGV reports followed failed raw WAV loads for experimental Quake/UT sounds. Exports contain imported/remapped streams. The sound bank now uses ResourceLoader and refuses missing streams before creating playback nodes. All 50 experimental sounds load and play through native AudioStreamPlayer3D in both exported PC packs; Windows pack validation used Linux Godot, not Windows execution.
- A landing correction could apply the difference between historical falling velocity and grounded server velocity as a new upward impulse. A real-physics phase/latency fixture reproduced 20 erroneous corrections across ten jumps in one timing case. Ground-contact corrections now preserve newer jumps and actual impulses without adding landing bounce. The defect predates the latest networking optimization.
- Brief trigger taps between 30 Hz input sends could disappear. Numbered, bounded trigger edges are repeated until acknowledged and consumed once by the authority. Actual ENet tests fired exactly one downward rocket per case, including synthetic tracked hands and a dropped first input packet; explosions damaged and boosted the shooter. This reproduces a possible cause of the reported missed rockets, not proof of every missed shot in the original session.
- The subsequent rocket-jump test reproduced taps discarded just before cooldown ended, including offline practice. Quake and Doom rocket launchers now buffer a primary tap for up to 250 ms without shortening cooldown; offline practice uses the same fire-edge handling. Both loadouts pass local and ENet timing, jump-height, self-damage, cancellation and replication checks. See [rocket-jump validation](ROCKET-JUMP-HOTFIX.md) for measurements and headset feedback.
- Empty tracked weapon swings and kicks could impose a 300 ms firing lock while re-aiming or jumping. Tracked movement now locks ranged fire only on actual melee contact. Axes, fists and explicit desktop melee retain their swing lock. Both launcher reproductions and existing melee/kick regressions pass.
- The cockpit camera excluded the pilot avatar/hand mesh layers. Those meshes now temporarily share its private layer and restore their original masks on exit. Gripping a nearby joystick enables its linked cannon pair; trigger fires, release restores automatic targeting. Authority checks pilot ownership, hand proximity, tracking validity and input freshness. Existing shared heat, firing rate and aim limits remain in force.
- Live WiVRn tracking exposed inferred feet displaced sideways around knee height. Ankle offsets now retain the calibrated calf-local transform rather than assuming the bridge uses a particular neutral bone axis. Real foot joints retain priority; deliberate leg lifts still control IK.
- Leg assistance detects planted feet while idle. It can activate on the first movement frame after standing still, and resumes within 350 ms after a physical step settles, replacing the previous roughly 0.8-second wait.
- Physical crouch/prone speeds measured correctly at 5.17/1.692 m/s versus 9.4 standing in the controlled rig. The worn headset also reached these reduced speeds. A floor-level headset below the old 18 cm validity limit could fall back to standing; the minimum is now 5 cm while collision height remains bounded at 65 cm.
- The Quake axe assets were derived from a chainsaw recording. Four axe clips now use original CC0 filtered-noise swing sounds. Other sounds retain their original hashes and levels.
- Quake launch calculations matched the authoritative muzzle. Live moving-player captures showed roughly 16–26 cm separation from the interpolated view, versus around 1 mm while stationary. Projectile nodes now use one presentation interpolation path, with the initial local VR sample aligned to the visible muzzle; physical trajectories remain unchanged.
- Quake railgun trails and brief shotgun pellet streaks/impact puffs are now explicit effects. Shotgun muzzle positions sit just beyond the model front face. Flashes follow weapon orientation and extend outward from the muzzle. Effects retain the existing particle and shape budgets.
- The VR rig could read weapon data after the local state became inactive while its fighter remained alive. It now skips that stale actor and stops visual updates while quitting.

## Validation and limits

Source regressions cover landing reconciliation, input delivery, replication, stance speeds, low-headset pose validation, bridge ankle orientation, physical VR inputs, weapon rules, cockpit ownership/control and shared cannon heat. Vulkan visual tests cover the real synthetic VR rig, moving Quake launches, shotgun/rail effects, cockpit body layers and menu/focus release. Replays accept the new optional fire acknowledgement while retaining old-frame compatibility.

Selected screenshots and full local logs are in ignored `test-results/live-crashes-0.11v/`; private recordings, tracking samples and core dumps are not distributed. Some automated scene teardown fixtures emit pre-existing ObjectDB/resource warnings; successful assertions should not be read as an assertion that every engine log is warning-free.

The final native Linux package passed three actual WiVRn runs (Quake practice, AS/UT and TB/Quake), each reaching XR_READY and DM_HOST_READY, then exiting with code 0 on its 20-second timer and no script/engine errors in its engine log. These are bounded smoke tests, not full matches.

Linux and Windows candidates are in `Builds/Hotfix-0.11v/`. They are replacement executable/PCK/library sets and require the existing 0.11v asset installation (local tests use `--asset-root` pointing at the workspace). They have not been published. The server must receive the corresponding source update for acknowledged trigger events and authoritative manual cockpit control. Actual Windows/VirtualDesktop execution and a fresh remote two-player acceptance session remain unverified.

Release runtime terminal output is buffered. Native acceptance must use the explicit engine log as well as process exit status. The stock export runtimes disable path overrides, so external `--script` probes are not a valid substitute for normal packaged gameplay.
