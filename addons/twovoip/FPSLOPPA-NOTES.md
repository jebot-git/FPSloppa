# TwoVoIP integration

Pinned release: [TwoVoIP v6.5](https://github.com/goatchurchprime/two-voip-godot-4/releases/tag/v6.5), MIT. Native binaries are unmodified upstream release artifacts (see BINARY-SHA256.json). Included targets match FPSloppa releases: Linux/Windows x86-64 and Android. Godot 4.6 or newer is required. Dependency copyright notices are included alongside LICENSE.txt.

FPSloppa uses the native resampler, RNNoise and Opus encoder, plus AudioStreamOpus and the upstream speaker's reorder/jitter buffer. The old ADPCM and generator pipeline has been removed. `deathmatch/voice/microphone.gd` extends the upstream microphone helper and supplies permission/PTT/VOX control, bounded processing, retained resampler leftovers, and avatar mouth input. Fixed network format: 48 kHz mono, 20 ms, 24 kbps Opus. Each packet has its own per-sender sequence; unordered unreliable ENet transport avoids one sender discarding another sender's voice. The relay validates frame configuration and size, admission, replay window and rate limits without decoding on the dedicated server.

Local changes to the upstream speaker helper: drain reordered tails on timeout, play very short utterances, prevent duplicate queue-count inflation, expose decode instrumentation, reduce adaptive pitch changes to 0.98–1.02, and suppress per-packet diagnostic printing. The game sets an 80 ms target and 60 ms tolerance, caps reordering/gaps before entering native playback, ends stalled streams after 160 ms, and frees idle speakers after two seconds. Headless dedicated servers do not instantiate speakers. Positional voice uses AudioStreamPlayer3D directly so its native Opus playback is available independently of Steam Audio's inner-player lifecycle.

Listen-only, PTT (initial default), VOX, per-player mute, microphone selection, Android permission requests and voice volume remain available. Existing `sv_voice_backend builtin` now means TwoVoIP. External Mumble remains an optional dedicated-server handoff; it is not used by the built-in relay. Network protocol 19 requires all peers to use the updated client/server.

The microphone helper rebuilds its resampler if the input rate changes and checks native encoder creation failure. Device switching stops capture before selecting the new driver, opens the new input before configuring its encoder, and performs one restart per menu selection.
